## 텔레메트리 설정

이 인스턴스가 자기 분석 데이터를 어디로 보낼지는 `posthog/telemetry.py`의 `get_telemetry_target()` 한 곳이 정한다.
서버 전역 SDK, `ph_client.get_client`, 사용량 보고, 비동기 마이그레이션 이벤트, LLM 평가 이벤트, 브라우저 `posthog-js`, 툴바가 모두 이 함수를 거친다.
코드에 박아 둔 PostHog 클라우드 키와 호스트는 서버와 브라우저 경로에서 지웠다.

| 설정                                          | 기본값  | 뜻                                                                                                       | 근거                                 |
| --------------------------------------------- | ------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| `POSTHOG_TELEMETRY_HOST`                      | 빈 값   | 수집 서버 주소. `http://` 또는 `https://`로 시작해야 한다                                                | `posthog/settings/base_variables.py` |
| `POSTHOG_TELEMETRY_API_KEY`                   | 빈 값   | 수집 서버 프로젝트 키. 브라우저에도 같은 값을 넣는다                                                     | 같음                                 |
| `OPT_OUT_CAPTURE`                             | `false` | 참이면 위 두 값이 있어도 아무것도 보내지 않는다. `str_to_bool`로 읽으므로 문자열 `"false"`는 끄지 않는다 | 같음                                 |
| `POSTHOG_TELEMETRY_USAGE_REPORTS`             | `false` | 사용량 보고(조직, AI observability)와 LLM 평가 실행 이벤트를 보낼지                                      | 같음                                 |
| `POSTHOG_TELEMETRY_USAGE_REPORTS_INCLUDE_PII` | `false` | 사용량 보고의 사용자 목록에 이메일과 이름을 더할지. 아래 "보내는 개인정보" 참조                          | 같음                                 |

판정 규칙은 다음과 같다.

- 호스트와 키가 둘 다 있어야 수집 서버로 본다. 키만 있으면 SDK가 PostHog 클라우드 호스트로 가므로 전송 없음으로 처리한다. 호스트가 `http(s)`가 아니면 브라우저가 자기 origin의 경로로 읽으므로 이것도 전송 없음이다.
- `OPT_OUT_CAPTURE`가 참이면 수집 서버가 있어도 전송 없음이다.
- 사용량 보고는 위에 더해 `POSTHOG_TELEMETRY_USAGE_REPORTS`가 참이어야 한다(`get_usage_reports_target()`).
- 개발 모드(`DEBUG`)나 `SELF_CAPTURE`에서는 자기 인스턴스로 보내는 self-capture가 수집 서버 설정보다 먼저다. 서버와 브라우저가 같다. 하비 운영 설치는 `SELF_CAPTURE`가 꺼져 있어 수집 서버를 쓴다.
- compose는 `docker-compose.base.yml`의 `worker_env` 앵커로 위 다섯 값을 `web`, `worker`, `temporal-django-worker`, `migrate`, `asyncmigrationscheck`에 넘긴다. `.env`에 적으면 모든 Django 서비스에 닿는다.
- 수집 서버를 `.env`에 적을 때는 CSP도 따라간다. 수집 서버 origin을 `script-src`, `connect-src`, `style-src`, `font-src`에 더한다(`posthog/csp_middleware.py`).

하비 기본 설치는 `.env`에 아무것도 더하지 않으므로 이 경로에서 밖으로 나가는 텔레메트리가 없다.
자기 PostHog 인스턴스로 받으려면 그 인스턴스의 프로젝트 키와 주소를 두 값에 넣는다.

### `OPT_OUT_CAPTURE`의 의미

`posthog/settings/base_variables.py`가 `str_to_bool`로 한 번만 읽고, 서버 SDK(`apps.py`), `get_client`, 템플릿 컨텍스트(`opt_out_capture`), 프리플라이트 응답(`opt_out_capture`)이 모두 이 설정을 쓴다.
`y`, `yes`, `t`, `true`, `on`, `1`만 참이다. 문자열 `"false"`와 빈 값은 끄지 않는다.
예전에는 서버가 비어 있지 않은 값을 모두 참으로 읽어, compose 기본값 `"false"`도 서버 SDK를 껐다. 이제는 읽는 곳이 같다.
`docker-compose.base.yml`의 `worker_env`가 `OPT_OUT_CAPTURE: ${OPT_OUT_CAPTURE:-false}`를 모든 Django 서비스에 넘긴다. 하비 `web`에 따로 있던 줄은 지웠다.

### 프로세스별로 받는 값

| 하비 서비스                       | 텔레메트리 설정 5개를 받는가           | 근거                                    |
| --------------------------------- | -------------------------------------- | --------------------------------------- |
| `web`                             | 받음                                   | `docker-compose.base.yml`(`worker_env`) |
| `worker` (Celery 작업자와 beat)   | 받음                                   | 같음                                    |

### 원격 플래그가 정하는 동작

수집 서버가 없으면 서버 SDK가 꺼져 플래그 평가가 `None`을 돌려주고, 플래그에 기대는 동작은 코드의 기본값(꺼짐)으로 간다.
수집 서버가 있으면 로컬 정의에 있는 플래그는 로컬 값으로 평가하고, 로컬에 없는 키만 수집 서버의 `/flags`로 묻는다.
`sync_feature_flags_from_api` 관리 명령도 같은 수집 서버의 `/flags`에서 가져오며, 수집 서버가 없으면 건너뛴다.

| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| `disable-usage-reports`, `llm-analytics-disable-usage-reports` | 더 읽지 않는다. 사용량 보고는 `POSTHOG_TELEMETRY_USAGE_REPORTS`가 정한다                                                                                                 | 위 "사용량 보고"                                                   |
| `login-from-new-device-notification`                           | 새 기기 로그인 메일 발송. 수집 서버가 없으면 꺼진 상태가 기본이라 메일이 나가지 않는다. 켜지면 메일을 보낸 뒤 `get_client()`로 `login notification sent` 이벤트를 보낸다 | `posthog/tasks/email.py:login_from_new_device_notification`        |

### `get_client()`와 `ph_scoped_capture`

`posthog/ph_client.py:get_client`는 지역이 `US`·`EU`일 때 클라이언트를 만든다. 호스트와 키는 `get_telemetry_target()`에서 온다.
수집 서버가 없으면 호출자가 무엇을 주든 `disabled=True`로 만든다. 그래서 호출자는 `None` 검사 없이 쓴다.
`ph_scoped_capture`가 돌려주는 `ScopedCapture.__call__`은 `is_cloud()`일 때만 보낸다. 그래서 하비에서 `ph_scoped_capture`는 보내지 않는다.
이 `is_cloud()` 검사는 업스트림 self-hosted와 같은 동작이라 그대로 두었다. 열지 여부는 백로그 `buzzhog-zebn`에 있다.
`get_client()`를 직접 쓰는 곳은 이 검사가 없고, 수집 서버가 있으면 보낸다.

### `OPT_OUT_CAPTURE`를 켠 뒤에도 남는 경로

서버와 브라우저의 PostHog 텔레메트리는 모두 꺼진다. 아래는 이 설정과 무관하게 남는 외부 호출이다.

- 툴바 인증 페이지의 `stackpath.bootstrapcdn.com` 스타일시트.
- 기본 제3자 자원, 커뮤니티 스킬 동기화, 하비 설치·업그레이드 스크립트, desktop 앱 업데이트 확인.
- 하비 설치 스크립트와 Go 설치기, 인프라 도구(`toolbox`)의 하드코딩 키 전송. 백로그 `buzzhog-zebn`이 다룬다.

## 프런트엔드 외부 origin (CSP)

`CSPMiddleware`가 HTML 응답마다 정책을 만든다.
하비(자체 호스팅)에서는 앱 정책을 `Content-Security-Policy-Report-Only`로 보낸다. 브라우저는 위반을 막지 않는다. 하비는 `CSP_REPORT_ENDPOINT`가 비어 있어 `report-uri`도 붙지 않으므로, 위반은 어디로도 보고되지 않고 브라우저 콘솔에만 남는다. 강제되는 것은 `frame-ancestors`뿐이다.
그래서 자체 호스팅에서 CSP는 외부 호출을 막는 장치가 아니다. 아래 목록은 "허용하는 범위"로만 읽는다.

## 업데이트 확인

서버(Django)가 설치된 버전을 PostHog 서버에 물어보는 코드는 찾지 못했다.
검색한 이름: `check_for_updates`, `latest_version`, `version_check`, `UPDATE_CHECK`, `get_latest_version`. 매치는 테스트와 SDK 상태 API(`posthog/api/sdk_health.py`, SDK 버전이며 PostHog 자체 업데이트 확인이 아님)뿐이었다.
desktop 앱은 PostHog 업데이트 피드를 확인한다(위 절).
`releases.posthog.com`은 PostHog CLI 설치 스크립트와 릴리스 산출물 주소다(`cli/README.md`, `cli/CHANGELOG.md`). 서버가 부르는 호출이 아니라 사용자가 CLI를 설치할 때 쓰는 주소다.
